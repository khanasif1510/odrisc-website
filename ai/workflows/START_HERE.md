# Start Here — AI and Developer Workflow

## Before Starting Any Task

1. Read `AGENTS.md`.
2. Read `PROJECT_CONTEXT.md`.
3. Identify the relevant source-of-truth documents.
4. Inspect the existing repository implementation.
5. Confirm the scope of the requested change.
6. Identify assumptions and unresolved questions.
7. Define acceptance criteria.

## Task Classification

Classify the task as one of the following:

- Product definition
- Content
- Page design
- Component design
- Frontend implementation
- Animation
- SEO
- Accessibility
- Analytics
- Performance
- Refactoring
- Bug fixing
- Documentation

## During the Task

- Keep changes focused.
- Follow approved patterns.
- Reuse components.
- Avoid unrelated improvements.
- Preserve accessibility and responsive behavior.
- Record important decisions.

## Before Completing the Task

Check:

- Does the result match the requested scope?
- Does it follow the source of truth?
- Does it maintain clinical integrity?
- Does it follow the brand system?
- Does it work across relevant screen sizes?
- Is it accessible?
- Is documentation affected?
- Were unsupported claims introduced?
- Were unrelated files changed?

## Completion Output

Summarize:

1. What changed
2. Which files changed
3. What was verified
4. Any assumptions
5. Any remaining open questions
